# FIRM-4B v2.2 experiment plan

## Why v2.2 exists

FIRM-4B v2.1 materially improved the compact specialist, but manual use exposed a
new failure mode that was not visible in non-thinking SFT evaluation:

- thinking mode can loop for hundreds or thousands of tokens,
- the model can consume its full generation budget and return no final answer,
- practical fabrication/process questions are sometimes answered too tersely,
- when pushed by a stronger system prompt to be more specific, the 4B model can
  become more willing to invent unsupported process details.

Inspection of the v2.1 trainer showed the cause of the reasoning mismatch:
`completion_encoding(..., enable_thinking=False)` was used for every training
example. v2.1 therefore fine-tuned final-answer behavior but did not directly
supervise Qwen3.5's reasoning channel.

v2.2 is a targeted correction, not a broad rewrite.

## Design

v2.2 starts again from the untouched pinned Qwen3.5-4B base revision:

`851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`

It inherits the complete v2.1 curriculum and adds:

- practical HgCdTe process/packaging targets,
- stronger recommendation/tradeoff answers,
- explicit correction of historical/material near-misses,
- HgCdTe wet-etch surface-chemistry distinctions,
- Te-rich LPE mercury-partial-pressure reasoning,
- die-attach thermal/mechanical tradeoffs,
- additional diagnostic/mechanism-calibration examples,
- a sparse set of short supervised Qwen reasoning traces.

The reasoning traces are intentionally a small fraction of the data. They teach
the pattern:

`identify the governing distinction -> resolve it -> give the final answer`

rather than rewarding long chains of repetitive self-checking.

## Frozen dataset candidate

Generated by:

`scripts/build_firm4b_v2_2.py`

Current candidate:

- 5,150 training examples
- 447 validation examples
- 62 reasoning-trace rows total
- 12 unique reasoning-trace targets
- 56 process-engineering rows
- 379 diagnostic-reasoning rows
- 125 contrastive-correction rows
- 2,355 quantitative rows
- 26 out-of-scope rows

The exact user stress prompts remain outside training. Their lowercase SHA-256
hashes are used only as contamination guards. The literal prompts live only in
the ignored `runs/private-evals/` area.

A separate public adversarial set is frozen at:

`evals/firm_v22_gauntlet_v1.jsonl`

The v2.2 trainer rejects exact overlap with that gauntlet.

## Training profile

`scripts/train_firm4b_v2_2.py`

- exact pinned Qwen3.5-4B base
- BF16 LoRA
- language MLP targets only
- rank 16
- alpha 32
- LR 1.5e-5
- effective batch 4
- sequence length 1024
- 1,290 optimizer steps
- approximately one effective pass
- eval every 258 steps
- checkpoint every 125 steps
- frozen-weight fingerprint before/after
- explicit provisional-data opt-in

Ordinary examples are encoded with `enable_thinking=False`.
Reasoning-trace examples use the native Qwen3.5
`assistant.reasoning_content` path with `enable_thinking=True`, supervising a
short rationale, `</think>`, and the final answer.

## Release gates

v2.2 is not improved merely because training converges.

It must be compared against:
- untouched Qwen3.5-4B,
- FIRM-4B v1,
- FIRM-4B v2.1,

with thinking disabled and enabled where supported.

Critical gates:

1. no empty final answer after long thinking,
2. lower reasoning-loop/token-budget failure rate,
3. no regression in v2.1 material identity/taxonomy,
4. process answers become more useful without increased fabrication,
5. correct HgCdTe wet-etch family/tradeoff guidance,
6. correct Te-rich LPE Hg-pressure/containment reasoning,
7. correct Willoughby Smith photoconductivity history,
8. better die-attach engineering guidance,
9. preserved typo/scope robustness,
10. preserved quantitative/model-selection performance,
11. Q4_K_M laptop/Ollama footprint and throughput remain practical.

## Runtime policy

Do not solve reasoning-budget failures solely by increasing `num_predict`.
Manual testing showed that even a 2,048-token generation cap can be consumed
entirely by reasoning on some process questions.

Runtime headroom is still useful as a safety margin, but the preferred fix is to
make reasoning itself shorter, better calibrated and more decisive.

Math-heavy execution should increasingly use deterministic tools. FIRM's core
responsibility is to select the correct physics/model, state assumptions and
units, route the computation, and sanity-check the result.
